# Synctappy Design System

Source of truth for how the Synctappy landing page looks, moves and speaks.
Tokens live in `app/assets/css/main.css` (`@theme`). If this doc and the CSS disagree, fix one of them. Don't let them drift.

**Design philosophy:** *Simple enough to understand. Premium enough to trust. Powerful enough to grow with the business.*
Futuristic-soft, premium, clean, calm (blueprint §13). Product first, decoration second.

## 1. Source-of-truth hierarchy

1. `Gambaran_Landing_Synctappy.png`: visual reference for composition, hierarchy, card shapes and rhythm.
2. `SyncTap_Master_Product_Blueprint_Synvora.docx`: features, plans and compliance. Never invent features beyond it.
3. `index_synctappy.html`: old prototype, used only for copy and component ideas.

Where they conflict: **reference image > old HTML**, and **Synctappy identity > generic SaaS patterns**.
The site is bilingual (EN / ID) and follows the device language; see the language switcher in §6. Indonesian copy should read as natural marketing Bahasa Indonesia, not a literal translation, and keep feature names (Multi-Link, Smart Profile, Dynamic Link, Google Review) as product terms. Indonesian strings run ~10–20% longer, so check layouts in both languages (the hero H1 uses a slightly smaller clamp for `id`).

## 2. Brand

* Name: **Synctappy**, always with endorsement **by SYNVORA** (lowercase "by", uppercase tracked "SYNVORA").
* Positioning: *Smart Touchpoint Platform*. Tagline: **Tap. Connect. Grow.**
* Core concept: TAP / SCAN → DIGITAL EXPERIENCE → ACTION → ANALYTICS.
* Demo business used in all visuals: **KopiKu Coffee & Eatery** (matches the supplied photos). Always label it demo.
* Short link format shown in UI: `go.synctappy.biz.id/<slug>`.

## 4. Typography

* **Space Grotesk** 500–700 → `font-display`, all `h1–h4`, big numbers, prices. Letter-spacing −0.02em (hero −0.035em), `text-wrap: balance`.
* **Plus Jakarta Sans** 400–800 → `font-sans`, everything else (body, buttons, nav, labels, pricing text, footer, wordmark).

| Role | Size |
|---|---|
| Hero H1 | `clamp(2.6rem, 5.3vw, 5.1rem)`, leading 1.02 |
| Section H2 (`UiSectionHeading`) | `clamp(2rem, 4.2vw, 3.25rem)`, leading 1.06 |
| Final CTA H2 | `clamp(2.8rem, 6vw, 5.5rem)` |
| Lead | 16 → 18px (`md:text-lg`), `ink-500` |
| Eyebrow | 11.2px bold, uppercase, tracking 0.16em, brand-600, outline pill with gradient dot |
| Body small / card text | 14px `ink-500` |

H2 pattern: `title` in ink + `highlight` phrase in gradient (use `stack` to force the highlight onto its own line for centered headings).

## 5. Layout & spacing

* Container `.container-x`: max 1240px, gutters 16/24/32px.
* Section rhythm `.section-y`: 80px → 112px (md). Backgrounds alternate white / `mist-50` / light gradient. One dark inset panel mid-page (Dynamic Link) and a dark finale (Final CTA).
* After the hero, content sits on a **white rounded sheet** (`rounded-t-[2rem→2.75rem]`) overlapping the hero, as in the reference. The footer repeats that rounded-top overlap on the dark CTA.
* Radii: cards `--radius-card` 20px, panels `--radius-panel` 28px, buttons 12px (`rounded-xl`), chips full.
* Shadows: `--shadow-soft` (resting cards), `--shadow-lift` (hover/highlight, blue-tinted), `--shadow-device` (phones, hero image).

Breakpoints verified: 1440, 1280, 1024, 768, 640, 390, 375, with no horizontal overflow. Mobile rules: hero stacks (copy → visual), CTAs go full width, card rows become horizontal snap scrollers (Campaign, Use-case tabs), the nav collapses into a hamburger panel.

## 7. Motion

* Scroll reveal: `v-reveal` / `v-reveal="120"` / `v-reveal="{ delay, variant: 'fade' }"`. The element fades in and rises 24px from scale 0.985 over 0.8s (ease-out-expo), once. Elements are hidden only when `html.reveal-ready` is set by an inline head script, so without JS everything stays visible.
* Hero uses CSS-only `.hero-in` (staggered `--d`) so above-the-fold content never waits for hydration.
* Ambient: `animate-float` (7s, 10px) on one hero callout, `animate-pulse-ring` on NFC signals, `animate-dash-flow` on `UiFlowConnector` lines. Nothing else loops, except the Dynamic Link auto-cycle (3.2s), which runs only while that section is in view, stops on user choice and is disabled by reduced motion.
* Progress effects: the How-It-Works line, analytics line draw and bar fills are triggered by the parent `.is-visible` via Tailwind `in-[.is-visible]:`.
* Hover: lift ≤ 6px, glow via shadow, 300–500ms. Only `transform`, `opacity` and `box-shadow` are animated (GPU-friendly).
* `prefers-reduced-motion: reduce` disables all transitions and animations and shows reveals immediately.
* Don't use bounce, spin loops, parallax, heavy blur stacks or glassmorphism beyond the hero callouts.

## 8. Content & honesty rules (non-negotiable)

* **No em dashes (—) or en dashes (–) in visible copy** (product owner's rule: they read as AI-generated text). Use commas, periods, colons or parentheses instead; page titles use `|` as separator ("Synctappy | Smart Touchpoint Platform"). Check with `grep -rn "—\|–" app` before committing (code comments are fine).

* **Pricing:** plans come from blueprint §10, but the prices there are a pilot hypothesis. Show "Free" (14-day trial) and "Coming soon" only. Device limits (1/3/10/30) are shown.
* **Analytics numbers** are sample data. Always keep the "Sample data" badge and the figcaption.
* **Google Review compliance** (blueprint §17): no pre-filled 5 stars in review UIs, no "only show Google if 5★", no incentives, no promised review counts. Safe CTA copy: *"Share your experience on Google"*.
* **Campaigns** are labelled as templates/examples. Promos must never be tied to leaving a review.
* **No testimonials, customer logos or usage stats** until real ones exist (the reference image's testimonials were intentionally dropped).
* No fake auth or signup. CTAs open `LayoutCtaModal` (intents: `trial`, `signin`, `contact`).
* **Cookies:** never claim or set cookies that aren't real. The consent copy, the Privacy Policy cookie table and the code must always list the same cookies.

## 9. Accessibility

Semantic landmarks (header/nav/main/footer), one H1, one H2 per section with `aria-labelledby`, a skip link, visible `:focus-visible` rings (2px brand-600), `aria-expanded` on the hamburger, and a native `<dialog>` for the CTA modal (focus trap + Esc). Use-case tabs follow the ARIA tabs pattern with arrow-key navigation, and the Dynamic Link switcher is a radiogroup. Decorative SVGs are `aria-hidden`, and meaningful images have descriptive alt text. Text colors pass AA on their backgrounds (`ink-400` is used only for hints and small labels, never for essential content).
